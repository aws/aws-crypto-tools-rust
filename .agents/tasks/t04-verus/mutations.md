# T04 model mutation check

Target: `verus-proofs/t04_branch_key_wrap.rs` (model-level proof of `branch_key_wrap::wrap`, VR-2026-T04, TM-MPL-012).

Tool: Verus 0.2026.07.12.0b42f4c (release, macos_aarch64, toolchain 1.96.0). Repo `esdk-native-mpl`, branch `MPL-Verus`, HEAD `d6e42d8` (proof file is untracked at the time of the run). Re-run after the review fixes in `review-response.md`; all lines below are from that re-run.

Method: each variant is a copy of the proof file in `/tmp/t04work/mut/` with one deliberate change to the MODEL (never to `verus-proofs/`). Each copy is run under Verus. A variant counts as rejected when Verus exits 1 and reports at least one error. The control (M0) is the unmodified copy. The script is `mutate.py` in this directory (it reads the proof file and writes the copies to `/tmp/t04work/mut/`; the copies are regenerated by it, so they are not stored here). Run it with `python3 mutate.py`.

What a rejection shows: the proof is sensitive to that change. It does not show the shipped code is right, because the proof is about a model. A rejection from an intermediate `assert` in the proof body counts: Verus assumes a failed assert afterwards, so the first reported error is the place where the model and the specification stop agreeing.

Command for every row: `~/verus/verus /tmp/t04work/mut/<id>.rs` (the control file is `M0_baseline.rs`).

All of M1 to M16, MB and MC were rejected (exit 1, at least one error). The control passes with 45 verified, 0 errors.

MA is a survivor and it is expected. MA makes `wrap` return `Err` right after the log setup, so it never succeeds. It still verifies (exit 0) because every `ensures` about the draws and the layout has the form `r is Ok ==> ...` (partial correctness). The proof therefore does not show that `wrap` can return Ok; this is stated in the proof header, section 6, "Termination with Ok". If the same `return Err` is placed as the literal first statement of `wrap`, it is rejected, but only because `log_extends(old(rng).log@, final(rng).log@)` then lacks its reflexivity lemma, not because of any claim about Ok.

MC is the variant most relevant to the honesty point: a failing salt draw is ignored and `wrap` carries on with the zero-initialized salt. Verus rejects it at the log-entry assertion, so the model cannot silently use a salt that the generator did not fill.

M12 is caught by `lemma_constants` (an arithmetic check on constants), not by `wrap`. Low value; kept for completeness.
