## B. Overclaims / claims stronger than the proofs
B1. **C03 is presented as implemented, but its `hkdf` / `hkdf_expand` clauses are not proved.** `verification-recommendations.md:52-53` says "C03's `hkdf*` functions are covered by the existing VR-009 prim half and are not re-proven"; `verus-proofs-report.md:106-112` says C03 "is in-crate as VR-013 ... and VR-014"; the status rows (`verus-proofs-report.md:725-726`, `verification-recommendations.md:250-251`) say "In-crate" with no "partial". The C03 block (`02-capability-driven.md`, C03 `property`) also requires "hkdf/hkdf_expand Ok => |okm| in {16, 24, 32}" and "No listed function panics" including `hkdf`, `hkdf_expand`. VR-009 prim half proves only the decision fn `hkdf_key_len_ok`, `salt_size_core`, `no_salt_slice_core`; the adapter calls `Salt::new`/`extract`/`expand`/`fill` are unmodeled (notes-2 section 8b item 1), and `verus-proofs-report.md:493-496` itself says the aws-lc-rs HKDF results are not proven. No doc lists the unmet C03 parts (hkdf/hkdf_expand end-to-end length and no-panic; `DigestContext::digest`'s inner `finish()` call, notes-2 8b item 2). Fix: say "C03 partly in-crate" and list the remainder.
B2. **`Ok => old ++ ct ++ tag` is stated as a proved result, but it is an in-body `assert`, not an `ensures`.** Only `verus-proofs-report.md:579` says "(in-body assert)". Other places drop the caveat: `verification/README.md:109` ("`Ok` => `old ++ ct ++ tag`, length ..."), `verification-recommendations.md:251` ("`Ok` gives `old ++ ct ++ tag`"), `:988` (listed under `verus_proven` as a postcondition), `verus-proofs-report.md:584,726` ("BUG-07(a) **proved** ... `old ++ ct ++ tag` (+16) on `Ok`"). The `ensures` of `aes_encrypt_core` gives only prefix and total length (notes-2 6a), so no caller can use the tag-order fact. The +16 also rests on trusted A19. Only the key/nonce `Err` and the seal-`Err` length/prefix facts are `ensures`. Fix: add "(asserted in the body, not exported)" and "+16 relies on A19" in README, recommendations and the status row.
B3. **"A longer buffer ... ends in a callee-side `Err`" (`verification/README.md:110`, `verus-proofs-report.md:585,726`, `verification-recommendations.md:251`) is stronger than the postcondition.** The core proves `Err` and `!PlainTooShort` (notes-2 6b ii). That also admits `InvalidKey` / `InvalidNonce`; "rejected by the open/gather step" is true only if key and nonce are valid. Also `!PlainTooShort` is a direct consequence of the VR-006 `iff` (notes-2 6b i), so the only new content is `Err` for a long buffer, which comes entirely from A-OPEN. The docs do label it A-OPEN-relative, so this is wording precision, not a hidden assumption. F2 (`verus-proofs-report.md:601-604`) states the "authentication tag did not match" mapping as test-pinned, which is correct; that mapping is adapter code and unverified.
B4. **Unconditional "no panic" wording vs the F4-only caveat.** `verification/README.md:104-105` (kbkdf "no panic path"), `verus-proofs-report.md:544-546`, `verification-recommendations.md:941` (property: "never panic"). The report's TCB intro (`:640-642`) says every listed call is trusted not to panic, which is the right blanket statement. But only `Context::finish` is named as a documented panic (F4, `:560-564`). notes-3 section 3 found three more documented `expect` sites reachable through trusted A7/A8 (`hmac::Key::new` `hmac.rs:297-299`, `Context::with_key` clone `hmac.rs:205`, `hmac::sign` `hmac.rs:391,425`). They are covered by the blanket sentence but not enumerated, so the hmac row reads as unconditional. Low severity.
B5. **`ct_equal_core` ensures is near-vacuous but listed as a result.** `verus-proofs-report.md:533` and `verification/README.md:106` state "result is the `Ok`-ness of the aws-lc-rs comparison" and "no claim about equality semantics or timing". That is honest, but it is A13 restated (notes-2 5b, notes-3 section 4); the same applies to `fill_random_core` ("Totality only"). The docs do say so (`verus-proofs-report.md:677-679` footnote). No change needed beyond noting these two rows add no independent evidence.
